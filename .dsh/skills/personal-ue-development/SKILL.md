# 个人 Unreal Engine 开发辅助流程

## 工作边界

- 先识别工程使用的 Unreal 版本、目标平台、插件、模块和当前工作区；不要假定 UE6 API 已经稳定，也不要把 UE5 的接口直接当作未来版本保证。
- 把技术美术、程序、美术、图形学和游戏设计的判断分开记录；有数据时优先引用数据，没有数据时标记为假设。
- 先做只读分析和影响范围预览。删除、移动、重命名、批量修改资产或修改项目配置前，必须明确目标范围、引用风险和恢复方式。
- 将编辑器专用逻辑、运行时逻辑和打包逻辑分开验证。编辑器中能运行不代表 PIE、Standalone 或打包结果可用。

## 推荐流程

1. 读取 `.uproject`、插件、模块、配置和相关资产路径。
2. 描述问题的可观察症状、收集范围和未知信息。
3. 先使用只读工具检查资产、引用、材质、Shader、蓝图、渲染设置或性能数据。
4. 将发现分为事实、推断、风险和建议；不要把模型自述当作验证结果。
5. 如果需要修改，先生成变更预览，并保留可撤销或备份路径。
6. 修改后重新执行相同检查，比较修改前后的结果。
7. 报告源码、编译、引擎加载、运行时和打包验证分别达到哪一级。

## 常见任务口径

- 性能问题先区分 CPU、GPU、内存、IO、Shader 编译和资产规模，再选择采样或分析工具；没有基线数据时只提供诊断计划。
- 材质和纹理检查同时关注视觉目标、平台预算、纹理尺寸、压缩、采样器、Shader permutation 与实例复用。
- 资产“未使用”只能表示在明确扫描范围内没有找到引用；一次查询不足以证明可以安全删除。
- 编辑器工具需要考虑重复启动、回调清理、对象有效性、线程限制、长任务进度和取消后的部分状态。
- C++、Python、蓝图和材质节点的选择依据工程现有结构、运行时要求、维护成本与性能目标，不预设某一种实现方式。

## 输出格式

使用以下顺序回答或生成报告：

1. 结论或当前可确认的事实。
2. 检查范围与证据。
3. 影响、风险和未知项。
4. 建议的最小变更。
5. 验证命令或编辑器验证步骤。

如果没有真实 Unreal 工程、日志或性能采样，只能给出通用方案和需要补充的证据。
